# Gym Tracker PWA Implementation Plan

> Executed inline (superpowers:executing-plans). Steps use checkbox syntax.

**Goal:** Ship the offline iPhone PWA described in `docs/superpowers/specs/2026-10-12-gym-tracker-design.md`.

**Architecture:** Pure-TS domain layer (`src/domain`) with no React/DB imports → Dexie data
layer (`src/db`) → React UI (`src/ui`, `src/screens`). Catalog + default program are static
data modules built from a curated free-exercise-db subset by a one-off script.

**Tech Stack:** React 18, TypeScript strict, Vite 5, Tailwind 3, Dexie 4, vite-plugin-pwa,
fflate, Vitest + fake-indexeddb, Playwright.

## Global Constraints

- Arabic RTL UI (`lang="ar" dir="rtl"`), dark theme, iPhone-first (safe-area insets).
- Must work fully offline after first load; HashRouter; all assets precached.
- No runtime network calls. No analytics. No accounts.
- Domain functions are pure and deterministic (time passed in, never `Date.now()` inside).
- Weight unit kg; weight = load on one implement.

### Task 3: Domain logic (TDD)
Interfaces:
- `nextDayId(dayIds: string[], lastCompletedDayId?: string): string`
- `trainingWeek(firstSessionAt: number, now: number): number` (1-based)
- `isReturnPhase(week) → week <= 2`; `isDeloadWeek(week) → week % 7 === 0`
- `effectiveSets(block, week): number` (return phase → min(2, sets); deload → ceil(sets*0.6))
- `suggest(input: { exercise, block, history: SetLog[][] /* newest first, per session */ }): Suggestion[]` — one per side (or single), `{ side?, weight?, reps?, seconds?, reason: 'increase'|'hold'|'decrease'|'first' }`
- `e1rm(weight, reps): number | undefined` (Epley, reps 1–12)
- Tests: rotation wraparound/unknown id; week math boundaries; all sets at repMax → increase by increment; partial → hold; two sessions below repMin → −10% rounded to increment, never below 0; bodyweight (increment 0) → reps+1; unilateral sides independent; time metric +5s; first session → 'first'. Commit.
